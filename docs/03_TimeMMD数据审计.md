# Time-MMD 数据审计（第一版）

## 1. 数据身份

- 官方数据仓库：AdityaLab/Time-MMD。
- 数据包含数值序列和按二元时间戳对齐的文本序列。
- 数值数据含 `start_date`、`end_date`、目标变量 `OT` 和部分协变量。
- 文本数据含 `start_date`、`end_date`、事实 `fact` 和预测 `preds`。
- 原论文声明数据集采用 ODC-By v1.0；仓库当前快照根目录未包含独立 LICENSE 文件，正式报告需同时引用论文许可声明和具体原始数据来源。

## 2. 最重要的数据使用决定

模型只使用 `fact`，不使用 `preds`。

`preds` 是根据文本生成的未来预测，若作为输入参与预测，会引入强烈的未来信息和不可控的 LLM 先验。它可以用于分析数据构造过程，但不能作为正式模型输入。

文本必须满足：

\[
\text{text.end\_date} < \text{forecast origin},
\]

即文本在作出预测之前已经结束。与被预测区间重叠的文本不得使用。由于数据未单独提供真实发布时间，正式实现将采用保守的 `end_date` 截止规则，并在局限部分说明。

覆盖率定义为：一个数值时间区间内至少存在一条非空 `fact` 的比例。该统计只描述原始可对齐程度，不代表文本已经通过预测时点截断。

## 5. 已发现的质量问题

1. `Security_report.csv` 的 `fact` 和 `preds` 实质上全部为空，不能作为报告文本来源。
2. `Health_AFR_report.csv` 的事实缺失率约77.6%，不适合首批主实验。
3. 多个报告文件存在大量重复时间区间，不能把文本行数直接当作独立事件数量。
4. 搜索文本中出现明显主题漂移，例如交通文本混入证照、航空管理或其他国家道路法规。
5. 部分事实直接包含同一时间段的目标数值；只有在它严格属于历史输入窗口时才可使用。
6. 数值文件字段不完全统一，例如 `Date`/`date`、重复的日期字段和协变量缺失，需要按领域建立模式表。
7. 数据仓库当前包含10个数值目录，而初版论文主要描述9个领域；Health被拆为US和AFR，报告必须解释统计口径。
8. Climate 数值文件为时间倒序；Economy 文件顺序混乱并将 2024 年三行置于开头。任何建模前必须按解析后的时间稳定升序排序，不能直接按 CSV 行号切分。

## 6. 初步领域选择

第一阶段选择：

- **Energy**：多变量周序列、时间长度充足、报告稀疏，能检验门控是否在无文本时退回数值专家。
- **Climate**：文本覆盖高，适合检验多模态模型的潜在上限。
- **Economy**：月度样本少，适合少样本实验。
- **Traffic**：现实解释直观，适合报告案例和原型展示。

Environment作为算力允许时的日频外部验证。其余领域保留为扩展，不进入第3周关键路径。

## 7. 可复现审计

运行：

```powershell
python src/audit_timemmd.py
```

程序不会修改原始CSV，并生成：

- `outputs/audit/timemmd_numerical_audit.csv`；
- `outputs/audit/timemmd_text_audit.csv`；
- `outputs/audit/timemmd_audit.json`。

运行最小自检：

```powershell
python src/audit_timemmd.py --self-check
```
