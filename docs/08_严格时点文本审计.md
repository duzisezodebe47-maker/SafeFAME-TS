# 严格时点文本审计

## 1. 构造原则

对预测起点为 \(t\)、历史窗口起点为 \(t-L\) 的样本，文本事实必须同时满足：

\[
\text{fact.end\_date}\ge t-L,
\qquad
\text{fact.end\_date}<t.
\]

第一项把文本限制在与数值输入相同的历史观察窗口；第二项确保事实在预测开始前已经可用。等于预测起点或与预测区间重叠的事实被排除。

仅使用 `fact` 字段。`preds` 和 `pred` 在语料构造阶段即被排除，而不是交给模型自行忽略。

## 2. 语料审计结果

| 领域 | 来源 | 原始有效事实 | 精确去重后事实 | 删除重复 | 未来措辞标记率 |
|---|---|---:|---:|---:|---:|
| Climate | report | 582 | 582 | 0 | 8.59% |
| Climate | search | 1,868 | 1,660 | 208 | 8.01% |
| Economy | report | 435 | 435 | 0 | 15.63% |
| Economy | search | 2,313 | 2,308 | 5 | 7.19% |
| Energy | report | 354 | 354 | 0 | 7.35% |
| Energy | search | 2,299 | 2,274 | 25 | 10.20% |
| Traffic | report | 364 | 360 | 4 | 8.06% |
| Traffic | search | 2,280 | 2,186 | 94 | 9.70% |

最终语料共 10,159 条事实。相同来源中的完全相同事实只保留最早可用时间，避免重复转载人为增加文本权重。

“未来措辞标记”依据 `forecast`、`predict`、`expected`、`will`、`may` 等词进行启发式扫描。目前只作为审计特征，不自动删除，因为同一词也可能出现在历史转述中。正式语义实验将比较保留与过滤后的敏感性。

## 3. 样本级覆盖

- Climate：训练、验证和测试样本的 report/search 严格时点覆盖均为 100%；
- Economy：search 覆盖为 100%，report 在训练段约 74%、验证和测试段为 100%；
- Energy：search 覆盖为 100%，report 在早期训练段仅约 15%—16%，验证和测试段约 99%；
- Traffic：训练段任意文本覆盖约 77%，验证和测试段为 100%；早期 report 覆盖仅约 14%—16%。

不同时间段覆盖率变化很大，因此不能只报告全数据平均覆盖率。模型需要显式输入来源计数、缺失标记和距预测起点的时间距离。

## 4. 每样本选择规则

- report 和 search 分别最多保留离预测起点最近的 32 条事实；
- 保留来源标签，不将两类文本视为同质信息；
- 保存全部可用数量与实际选择数量；
- 保存最近文本年龄和平均文本年龄；
- 文本 ID 使用领域、来源、时间和规范化事实生成稳定哈希；
- 语料表与样本索引分离，避免反复复制长文本。

## 5. 风险与验证

1. `end_date` 是数据提供的时间区间终点，不一定等同真实网页发布时间；采用它是当前可复现条件下的保守近似。
2. search 事实数量多但存在主题漂移，必须与 report-only 结果比较。
3. 某些历史事实直接包含当期观测数字，只要发布时间早于预测起点即属于合法历史信息；仍需用文本打乱对照判断模型是否利用正确对齐。
4. 文本覆盖率高不代表语义有用，不能据此声称多模态模型会改进。
5. 未来措辞过滤是敏感性实验，不能仅凭关键词把全部句子认定为泄漏。

## 6. 可复现产物

- `data_processed/text/sample_text_index.csv`：预测样本到文本 ID 的严格时点映射；
- `data_processed/text/point_in_time_coverage.csv`：领域、跨度、数据划分级覆盖率；
- `data_processed/text/text_index_audit.json`：构造规则与清洗计数；
- `src/build_text_index.py`：统一生成程序及最小自检。
