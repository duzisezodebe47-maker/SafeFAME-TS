## 问题 1：5 个文件的哈希记录与实际提交内容不一致

### 现象

```bash
python src/verify_project.py
# FAIL: ('v4 evidence changed', 'outputs/safefame_v4/run_manifest.json')
```

### 证据

| 记录文件 | 目标文件 | 记录值 | 实际值 |
|---|---|---|---|
| `outputs/safefame_v4/verification.json` | `run_manifest.json` | `094de796…` | `cbd3c93c…` |
| `outputs/safefame_v4/verification.json` | `worker_execution.json` | `f19e267d…` | `61334e66…` |
| `outputs/attribution_audit_v4/summary.json` | `outputs/safefame_v4/summary.json` | `3935182f…` | `d9d1f162…` |
| `outputs/attribution_audit_v4/summary.json` | `outputs/safefame_v4/task_results.csv` | — | 不一致 |
| `outputs/attribution_audit_v4/summary.json` | `outputs/safefame_v4/candidate_results.csv` | — | 不一致 |

复现脚本：

```python
import json, hashlib, os
R = "."
v = json.load(open("outputs/safefame_v4/verification.json", encoding="utf-8"))
for n in ("outputs/safefame_v4/run_manifest.json",
          "outputs/safefame_v4/worker_execution.json"):
    got = hashlib.sha256(open(n, "rb").read()).hexdigest()
    print(n, "一致" if got == v["sha256"][n] else "不一致")

a = json.load(open("outputs/attribution_audit_v4/summary.json", encoding="utf-8"))
mapping = {"v4_summary":    "outputs/safefame_v4/summary.json",
           "v4_tasks":      "outputs/safefame_v4/task_results.csv",
           "v4_candidates": "outputs/safefame_v4/candidate_results.csv"}
for k, rel in mapping.items():
    got = hashlib.sha256(open(rel, "rb").read()).hexdigest()
    print(rel, "一致" if got == a["sha256"][k] else "不一致")
```

### 判断

`src/verify_v4.py` 第 27 行是在**验证当时就地计算** `run_manifest.json` 的哈希并存进
`verification.json` 的，这个字节锚定机制本身正确（跨机器比对有效）。

不一致说明：**`--record` 跑完之后，这些产物又被重新生成过** —— 推测是分阶段补跑实验时
更新了产物，但没有重跑依赖它们的验证与审计步骤。归因审计的 3 条记录同理，停在更早一轮
的 v4 产物上。

**这是流程同步问题，不涉及结果本身的可靠性。**

### 修法

在所有实验环节**最终确定之后**，按依赖顺序重跑：

```bash
python src/run_safefame_v4.py            # 若 v4 产物需重新生成
python src/verify_v4.py --output outputs/safefame_v4 --replay-models --record
python src/run_attribution_audit_v4.py   # 必须在 v4 产物冻结之后
```

**纪律：`--record` 必须是整个流程的最后一棒。** 之后再改任何被校验的文件，都必须重跑验证。

### ⚠️ 禁止事项

**不要手工修改 `verification.json` 里的哈希值来消除报错。**

那是伪造验证记录 —— 性质从「记录过期」变成「伪造记录」，属于学术不端。
这个问题只能通过在完整证据树上重跑来解决。

### 验收标准

```bash
python src/verify_project.py   # 不再出现 'v4 evidence changed' / 'attribution source changed'
```

## 问题 2：`verify_project.py` 在干净的 clone 上无法运行

### 现象

任何人克隆仓库后跑 `python src/verify_project.py`，第一条断言即失败。
README 中「复现与核验」一节对任何外部读者都是失效的。

**这同样影响你自己**：重装系统、换机器、重新 clone 之后也跑不通。

### 根因

脚本把「仓库内的紧凑产物」与「只存在于本地 / LFS 的重型证据」混在同一组硬断言里：

| 位置 | 问题 |
|---|---|
| `check_v4()` 第 152 行 | `assert digest(ROOT/name)==sha` —— 无 `is_file()` 保护。该记录含 3584 个文件，其中 3582 个是 `.gitignore` 明确排除的模型权重与逐任务指标。<br>**注意第 147-148 行的同类循环有 `if (ROOT/name).is_file()` 保护，152 行漏了。** |
| `check_v4()` 第 158 行起 | 逐任务读 `outputs/safefame_v4/tasks/*/audit.json`、`frozen_selection.json`、`metrics.csv` —— 整个 3600+ 文件的 `tasks/` 树不在仓库里 |
| `check_v4()` 第 195 行 | `(folder/'tasks').glob('*/models/*_cal_s*.pt')` —— 同上 |
| `check_attribution_audit()` 第 247 行 | `(ATTRIBUTION/'evidence').glob('*.npz')` —— `.npz` 证据不在仓库里 |
| `main()` v3 段 | 读 `outputs/safefame_v3/verification.json` —— 该目录不在仓库里 |
| `check_archive()` | 打开归档 ZIP —— 实体在 LFS 中，未 `git lfs pull` 时只有 134 字节指针 |

### 修法

让脚本区分「按设计不在仓库里」和「应该存在却缺失 / 损坏」：

```python
has_tree = (folder / 'tasks').is_dir()
if not has_tree:
    print('SKIP: 完整实验证据树不存在，跳过任务级交叉核对', file=sys.stderr)
    SKIPPED.append('v4 任务级交叉核对')
```

要点：

1. **跳过的项要在最终结论里如实声明。** 有跳过时不要打印 `PASS`，改为 `PARTIAL PASS`
   并列出未校验项，明确写出「不等于通过」
2. 缺文件的哈希校验跳过；**文件存在但哈希不符的仍要报出来**（那是问题 1 的真实缺陷，
   不能被静默掉）
3. `check_archive()` 可检测 LFS 指针（文件开头为 `version https://git-lfs.github.com/spec`）
   后跳过

参考实现：本地已按此思路打过补丁（**未提交，不在本仓库中**），可据此重写。

### 验收标准

```bash
# 在当前机器（无完整证据树）应能跑完并给出诚实的部分结论
python src/verify_project.py    # 退出码 0，输出明确列出被跳过的项
```

## 问题 3：`threadpoolctl` 未在 `requirements.txt` 中声明

### 现象

三个核心脚本直接 import，但 `requirements.txt` 里没有：

```
src/run_safefame_v2.py
src/run_safefame_v4.py
src/run_reviewer_sensitivity.py
```

### 证据

```bash
pip show threadpoolctl
# Version: 3.6.0
# Required-by: scikit-learn      ← 目前靠间接依赖才装上的
```

### 影响

scikit-learn 一旦不再依赖它，这三个脚本会直接 `ImportError`。
对强调可复现性的项目，这是明确的声明缺口。

### 修法

```

```

### 验收标准

```bash

pip show threadpoolctl            # Required-by 中应出现直接引用者
```

## 问题 4：`train_patchtst.py` 依赖被 gitignore 的第三方仓库

### 现象

```python
# src/train_patchtst.py 第 23 行
from models.PatchTST import Model as OfficialPatchTST
```

引用第三方代码而非内置，本身是合理做法。问题在于**获取步骤没有写进文档** ——
`docs/15_数据与代码来源清单.md` 只列出了出处，没有说明需要先克隆到 `references/external/`。

### 修法

在 `docs/15_数据与代码来源清单.md` 中补上明确的获取步骤，例如：

```bash
git clone https://github.com/yuqinie98/PatchTST references/external/PatchTST
```

并在 `src/train_patchtst.py` 的 import 处加一行注释说明该前置条件。

### 验收标准
