# 首轮基线审计与协议冻结

## 1. 审计结论

第一次基线运行成功暴露了原始文件顺序问题：Climate 数值文件为时间倒序；Economy 既非升序也非降序，2024 年的三条记录位于文件开头。直接按照 CSV 行号进行 70%/10%/20% 划分会破坏时间因果顺序，因此第一次运行的 Climate 和 Economy 数字已判定无效，不能进入论文。

代码现已统一执行：

> 解析时间区间 → 检查无效日期和负区间 → 稳定升序排序 → 记录移动行数和重复日期 → 再进行时间切分。

修复后已重新运行所有确定性和神经网络基线。Energy 与 Traffic 原文件本来就是升序，其复算结果保持一致；Climate 与 Economy 的结果发生明显变化，进一步验证排序修复不可省略。

## 2. 正式协议 v0.2

- 预测变量：各领域 `OT`；
- 数据顺序：依据数值区间起始时间稳定升序排序，绝不信任文件天然行序；
- 划分方式：按排序后时间顺序 70%/10%/20% 划分训练、验证和测试段；
- 标准化：均值和标准差仅由训练段计算；
- 缺失处理：先按历史方向前向填充，序列开头仍缺失时才使用训练段中位数；
- 模型选择：仅根据验证集确定正则参数或最佳训练轮数；
- 重拟合：确定超参数后，从头在训练+验证样本上拟合，测试集始终封存；
- 指标：标准化尺度 MSE、MAE、RMSE，并保存逐样本预测；
- 重复实验：确定性模型运行一次；神经网络使用 2026、2027、2028 三个随机种子。

## 4. 审稿式教训

1. 数据“时间范围正确”不能证明“行顺序正确”；审计必须显式检查单调性。
2. 程序成功运行和输出合理数值不能证明实验协议正确。
3. 任何衍生表格必须从修复后的正式结果文件自动重建，不能手工沿用旧数字。
4. 后续文本对齐必须使用同一排序后的数值索引，否则数值窗口与文本时点仍会错位。
5. 最终复现检查应故意对输入 CSV 打乱行序，确认排序后的结果不变。
