**验收基准：**2026-09-21；数据侧最新 `3218151885-creator@1cb8ca1`，交付目录 `辅助电脑02交付01次/`；模型侧 `SHY@887aed4`，交付目录 `03 辅助电脑二 交付一次/`。数据侧原先的 `eca3e30` 在验收过程中被强制更新为独立交付历史；逐文件比较确认其 `辅助电脑02交付01次/` 内容未变，故本轮紧凑证据复核仍适用。主控只读获取远端提交，在 D 盘 detached worktree 检查；没有改动或提交到辅助分支，也没有合并 `main`。

这两个判断是**阶段验收**。两份交付都不满足“整项课程设计的算法实验已经完成”的门槛。仓库中的数据和模型大文件按既有规则未入库；当前机器也没有交付方的 Python 3.12 完整环境，因此不能把他们记录的 19/87 项通过说成主控已独立复跑。

3. 独立核对模型侧 6 个候选清单与预测文件：每候选 1,008 行、合计 6,048 行，共同覆盖 252 个起点×4 步；无重复键或非有限预测，配置哈希、特征哈希、模型参数数及已记录的收益算术相符。预测中的生成提交 `0eb4df9` 是 `SHY` 当前提交的祖先。README 记录 87 项工程检查，但无法在本机独立复跑。

紧凑证据的独立算术检查可用本目录 `verify_first_deliveries.py` 重跑，显式传入两份交付目录。脚本仅使用 Python 标准库；它验证交付内部一致性，不重放模型训练或原始数据管线。

## 审稿式问题清单

### P1：正式集成阻断

- **协议不一致。** 主控 v1 使用 JSONL、整数起点、`cal/dec`；数据侧使用 CSV/NPY、字符串 `origin_id`、`calibration/decision`；模型侧用逐步 CSV、整数 `origin_id`、没有 `segment`，仅输出测试预测。哈希口径也不同：数据侧签名覆盖 Bundle，模型侧 `feature_hash` 只散列训练切片。不能直接拼接，也不能把这些哈希视为同一个量。
- **数据侧分支现在是独立历史的交付快照。** 远端 `1cb8ca1` 与 `main` 无共同祖先，根目录只有交付文件夹和说明，缺少它所依赖的 `src/`、`configs/`、依赖文件等。不能把该分支普通合并到 `main`，也不能在单独克隆该分支后按 README 的命令复跑。最终应由主控按固定提交和文件哈希**只接收交付目录**到完整仓库，再执行测试；不得整树覆盖导致旧实验、报告和配置删除。
- **模型入口仍锁在旧 v2 数据。** `train.py` 只接受 `v2smoke`，读取旧 `data_processed/semantic_features` 和原始 Time-MMD；未读取数据侧的冻结 Bundle。它的 70/10/20 划分与主控 v4 三折训练/校准/决策/测试四段不同。当前 6 候选表不能用作正式新方案的比较。
- **文本缺席时语义分支尚无显式掩码。** 数据侧交付了 `text_available`，模型侧 `FeatureBundle` 未包含它，`SemanticBranch` 对零向量做 PCA/标准化后仍可能产生非零贡献。必须在预测层实现并测试“无文本时 S 贡献为 0”，不能只依赖零向量。
- **频率含义被混淆。** 当前模型侧 `F` 是 10 维纯数值谱统计，不含语义×频率交互。`N+S+Q+F` 不能称为原 `frequency_residual` 的等价实现，+4.132% 冒烟值不能证明文本频率交互有效。
- **正式门控未实现。** 当前没有决策段 999 次逐行错位且每次重拟合尺度/PCA/正则的零分布，也没有两半段胜出检查、冻结路由或测试段独立计分。设计文件已将置换交换性测试列为待办，下一轮必须补齐。

### P2：表达和复现边界

- 数据侧 README 仍写“个人课程设计”，与老师课件和用户已确认的三人小组要求冲突；应修正为三人协作项目，不改变历史记录。
- 数据侧 `complete_source` 在现有数据中全空，因为没有逐条 URL；这只能作为来源元数据缺口报告，不能做“严格来源文本无效”的实验结论。
- 模型侧设计文档写旧分支名及“冻结后方可编码”，实际已完成工程代码；交付说明应对齐当前分支和状态。六候选中表现最好的 +4.132% 来自同一历史测试样例的事后观察，不能据此反向选定正式候选或宣称统计有效。
- 数据侧目前是 OT 单变量输入；若沿用历史多变量 DLinear-M 作主要公平对照，输入信息量不同。下一轮主要数值回退应从同一 OT 输入构造；多变量旧模型仅作标注清楚的历史参考。

## 下一次验收门槛
