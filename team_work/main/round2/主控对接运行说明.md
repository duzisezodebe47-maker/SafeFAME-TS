# 第二轮主控对接运行说明

本目录的 `split_spec_v2.json` 当前为 **DRAFT**。四项任务的切分边界来自 `configs/safefame_v4.json` 与数据侧第一轮申报的清洗行数；清洗序列文件 SHA256 尚未收到，不能修改为 `frozen`，也不能据此开始正式训练。正式模型预测不得沿用第一轮 `Climate_h4` 的 70/10/20 冒烟文件。

## 收到数据侧交付时

1. 在完整项目的独立检出中，按数据侧固定提交**只选择性导入**第二轮交付目录。`3218151885-creator` 是无共同祖先的交付快照，不能整树合并。记录提交号及逐文件 SHA256。
2. 对四个 `*_numerical.csv` 独立计算 SHA256，核对行数、`start_date`/`end_date`/`OT` 清洗规则、时间顺序和 `configs/safefame_v4.json` 的分折取整。只有核对通过后，才填入 `split_spec_v2.json` 的 `numerical_sha256`，写入 `approved_by` 和 `status=frozen`，提交冻结版本。不得仅把模板改名为正式协议。
3. 数据侧按冻结文件生成 Bundle。模型侧在本分支的 `prediction_contract_v2.json` 对照字段输出。`origin_id` 必须是字符串 `Domain:hH:fF:o<origin_index>`；`step` 为 1 至 H；目标与预测均为训练段标准化的 OT。
4. 主控收到 Bundle 时，从其 `manifest.json` 读取 `signature`，用如下命令严格核验整个目录的清单与哈希。这里和后续命令中的路径都应位于 D 盘：

```powershell
python -B team_work/main/round2/run_bridge.py validate-bundle --bundle <D盘Bundle目录> --bundle-signature <signature> --spec team_work/main/round2/split_spec_v2.json --task-id Agriculture_h12_f1 --scenario proxy
```

## 校准与决策阶段

先产生与 Bundle 同输入的 Last、SeasonalNaive、AR-Ridge 数值基线。Ridge 仅在训练段拟合，用校准段选择预注册 α；`N` 必须由模型侧从同一 Bundle 输出。

```powershell
python -B team_work/main/round2/run_bridge.py export-baselines --bundle <D盘Bundle目录> --bundle-signature <signature> --spec team_work/main/round2/split_spec_v2.json --task-id Agriculture_h12_f1 --scenario proxy --segments calibration decision --out <D盘阶段目录>/numeric_selection.csv
python -B team_work/main/round2/run_bridge.py validate-predictions --bundle <D盘Bundle目录> --bundle-signature <signature> --spec team_work/main/round2/split_spec_v2.json --task-id Agriculture_h12_f1 --scenario proxy --segments calibration decision --predictions <D盘阶段目录>/numeric_selection.csv <D盘模型选择期CSV>
python -B team_work/main/round2/run_bridge.py export-stage --bundle <D盘Bundle目录> --bundle-signature <signature> --spec team_work/main/round2/split_spec_v2.json --task-id Agriculture_h12_f1 --scenario proxy --segments calibration decision --predictions <D盘阶段目录>/numeric_selection.csv <D盘模型选择期CSV> --out <D盘隔离目录>/selection_stage
```

`selection_stage` 只含校准和决策目标。将其放在没有测试目标和测试预测的独立目录，在同一进程环境下执行冻结：

```powershell
$env:PYTHONPATH='team_work/main/src'
python -B -m team_eval freeze --task <D盘隔离目录>/selection_stage/task.json --samples <D盘隔离目录>/selection_stage/samples.jsonl --predictions <D盘隔离目录>/selection_stage/predictions.jsonl --nulls <D盘模型侧逐行重拟合零分布JSONL> --spec <D盘隔离目录>/selection_stage/spec.json --out <D盘隔离目录>/route.json
```

主控必须另外审计零分布生成代码和 999 次逐行错位、每次重拟合的记录；现有 `freeze` 入口只能独立重算经验 p 值，不能从 999 个数本身证明它们来自重拟合。若 `N+S+Q+SF` 没有真实语义×数值频谱交互或完整零分布，应在冻结前修订并提交候选注册，不能让它凭名称进入门控。

## 测试阶段

冻结路由文件写盘并记录 SHA256 后，才导出测试期数值预测，接收模型侧新生成的测试期预测，并创建**单独的** `test_stage`。其 `task.json` 和 `spec.json` 必须与 `selection_stage` 字节一致。`score` 读取冻结路由，不重新选候选。

```powershell
python -B team_work/main/round2/run_bridge.py export-baselines --bundle <D盘Bundle目录> --bundle-signature <signature> --spec team_work/main/round2/split_spec_v2.json --task-id Agriculture_h12_f1 --scenario proxy --segments test --out <D盘阶段目录>/numeric_test.csv
python -B team_work/main/round2/run_bridge.py export-stage --bundle <D盘Bundle目录> --bundle-signature <signature> --spec team_work/main/round2/split_spec_v2.json --task-id Agriculture_h12_f1 --scenario proxy --segments test --predictions <D盘阶段目录>/numeric_test.csv <D盘模型测试期CSV> --out <D盘隔离目录>/test_stage
python -B -m team_eval score --task <D盘隔离目录>/test_stage/task.json --samples <D盘隔离目录>/test_stage/samples.jsonl --predictions <D盘隔离目录>/test_stage/predictions.jsonl --spec <D盘隔离目录>/test_stage/spec.json --route <D盘隔离目录>/route.json --out <D盘隔离目录>/score.json
```

以上命令尚未在真实第二轮 Bundle 上运行。当前已运行的是 D 盘合成数据的 24 项单元测试，包括完整的选择期包、路由冻结与独立测试包打分。合成通过只证明接口与失败检查，不能当作真实模型收益。
